# Curriculum design

First Torch teaches decisions, not only recipes. Every lesson should answer five questions in this order:

1. **Goal:** What are we trying to achieve?
2. **Reason:** Why is it useful or safer?
3. **Steps:** What exactly should the player do?
4. **Common problem:** What is likely to go wrong?
5. **Proof:** What action or item demonstrates understanding?

## Writing rules

- Assume the learner knows basic WASD movement and looking around, but offer an early optional path for jumping, sneaking, sprinting, and combining movement controls.
- Introduce one new idea per quest.
- Name the exact inventory items and controls involved.
- Explain unfamiliar words on first use.
- Prefer a short task followed by immediate feedback.
- Use manual checkmarks only for observations or player-judged goals; use automatic tasks for concrete items.
- Never punish a learner for already knowing a step. A completed item in the inventory should satisfy the task immediately.
- Avoid valuable rewards that replace the skill being taught.
- Keep danger warnings specific and actionable.
- Keep chapter maps readable on smaller displays: wrap long paths into clear thematic rows before horizontal scrolling becomes necessary.

## Definition of done for a lesson

A lesson is done only when a beginner can follow it without verbal help, the completion condition is reliable, and both language versions fit comfortably in the quest window.
